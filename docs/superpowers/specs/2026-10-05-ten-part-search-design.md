# TermFlow: ค้นหา SOURCE แบบ 10 ช่วง

## เป้าหมาย

เพิ่มโหมดค้นหาศัพท์ที่แบ่ง SOURCE เป็น 10 ช่วงและประมวลผลพร้อมกัน เพื่อเพิ่มโอกาสพบศัพท์ใน SOURCE ขนาดใหญ่ ผู้ใช้เห็นความคืบหน้ารายช่วงและได้รับผลรวมชุดเดียว

## ขอบเขตและหลักประกัน

- ส่ง Prompt A ต้นฉบับแบบเต็มทุกคำขอ ห้ามแก้ ย่อ หรือสร้างสำเนาที่เปลี่ยนความหมาย
- แต่ละคำขอใช้ SOURCE เฉพาะช่วงที่กำหนด และใช้ VOCAB เดิมแบบอ่านอย่างเดียว
- ไม่เขียน SOURCE หรือ VOCAB และไม่รวมผลลง VOCAB โดยอัตโนมัติ
- ผลแต่ละช่วงต้องผ่าน STEP A strict validator ก่อนนำเข้าผลรวม
- ส่ง NEW ไป STEP B ได้หลังรวมผลสำเร็จและผู้ใช้เลือกศัพท์เองเท่านั้น; UPDATE ไม่ส่งต่ออัตโนมัติ

## การแบ่ง SOURCE และคำขอ

แบ่ง SOURCE ตามลำดับเดิมเป็น 10 ช่วง โดยถ่วงขนาดให้ใกล้เคียงกันและพยายามตัดที่ขอบย่อหน้า หากไม่มีตัวแบ่งย่อหน้าให้ใช้ขอบบรรทัด และหากเป็นบรรทัดเดียวให้ตัดที่ขอบ Unicode code point เพื่อไม่ให้ตัวอักษรเสียหาย เพิ่มย่อหน้าหรือบรรทัดข้างเคียงหนึ่งหน่วยที่รอยต่อเพื่อช่วยรักษาบริบท และเก็บ source offset ของช่วงจริงแยกจากข้อความ overlap

เปิดคำขอ AI ได้สูงสุด 10 รายการพร้อมกัน แต่ละรายการได้รับ Prompt A เต็ม, VOCAB read-only เดียวกัน, SOURCE fragment ของช่วงนั้น และ wrapper ที่ระบุหมายเลขช่วง โดยไม่เปลี่ยนกฎศัพท์ใน Prompt A การชน rate limit หรือข้อผิดพลาดชั่วคราวให้ retry เฉพาะช่วงที่ล้มเหลวด้วย backoff ที่เพิ่มตามครั้ง สูงสุดตาม Retry setting

## ความคืบหน้าและการยกเลิก

แสดงภาพรวม `เสร็จ X/10` และสถานะแยกรายช่วง: `รอ`, `กำลังค้นหา`, `กำลังตรวจผล`, `เสร็จ`, `ลองใหม่`, `ล้มเหลว`, `ยกเลิก` พร้อมจำนวน NEW/UPDATE ที่ผ่าน validation ในแต่ละช่วง

Cancel ยกเลิกคำขอที่กำลังทำงานทั้งหมดและไม่ทำ SOURCE/VOCAB เปลี่ยน ผลที่ยังไม่ครบ 10 ช่วงเป็นผลชั่วคราวใน session เท่านั้น ห้ามส่งต่อ STEP B หรือ export เป็นผลสมบูรณ์ ผู้ใช้ retry เฉพาะช่วงที่ล้มเหลวได้โดยเก็บผลช่วงที่ผ่านแล้วไว้

## รวมผลและข้อขัดแย้ง

รวมเฉพาะผลที่ผ่าน validation ทั้ง 10 ช่วง ตัด row ที่ซ้ำแบบ exact เดียวกันซึ่งเกิดจาก overlap ออกหนึ่งรายการ รักษาลำดับตามตำแหน่งแรกที่พบใน SOURCE

หาก CN เดียวกันได้ row หรือ section ต่างกัน ให้แสดงกลุ่มข้อขัดแย้งพร้อม candidate จากแต่ละช่วง ผู้ใช้เลือก candidate เองก่อนผลสุดท้ายจะพร้อม ห้ามเลือก TH/SEX/NOTE ที่ชนะด้วยคะแนนเสียง ห้าม merge field และห้ามซ่อน candidate การ resolve conflict เป็นการแก้เฉพาะ session workspace

## ผลลัพธ์

หลังทุกช่วงผ่านและข้อขัดแย้งได้รับการจัดการ ให้แสดงตาราง NEW/UPDATE รวมในหน้าผลเดิม และรองรับ Copy ตามเดิม เพิ่ม `บันทึกผลรวม` เป็น UTF-8 `.txt` ไฟล์เดียว รูปแบบคงหัวข้อ STEP A สองหัวข้อและแถว TSV จริง ไม่มีข้อมูลช่วงวิเคราะห์ปะปน

## History

เก็บ session เดียวที่มี Prompt ID/name/version/text/SHA-256, provider/model, SOURCE/VOCAB hashes, timestamp, และรายการช่วงทั้งสิบซึ่งประกอบด้วย offsets, fragment hash, raw response, parsed rows, validation result, retry count และสถานะรวม ห้ามบันทึก API key หรือเขียนทับไฟล์ SOURCE/VOCAB

## เกณฑ์ยอมรับ

1. SOURCE ทุกตัวอักษรอยู่ในช่วงจริงอย่างน้อยหนึ่งช่วง ลำดับช่วงไม่สลับหรือขาด และการแบ่งทำงานกับย่อหน้า/บรรทัดยาวและอักษรจีนได้
2. คำขอทั้งสิบใช้ Prompt A ข้อความ exact เดียวกันและ VOCAB exact เดียวกัน; SOURCE fragment ต่างกันตามช่วง
3. UI แสดง progress และสถานะรายช่วง; cancel/timeout/failure ไม่ freeze UI และ retry ช่วงเดียวได้
4. STEP A invalid ในช่วงใดช่วงหนึ่งห้ามรวมผลสมบูรณ์หรือส่งไป polish
5. duplicate row จาก overlap ถูกลบ; CN conflict แสดง candidate ทั้งหมดและต้องให้ผู้ใช้เลือกเอง
6. ผลรวมเมื่อพร้อม export มีสอง sections ตามลำดับเดิม, ผ่าน STEP A validation อีกครั้ง, และบันทึกเป็นไฟล์เดียวได้
7. Read-only tests ยืนยัน SHA-256, size และ mtime ของ SOURCE/VOCAB ไม่เปลี่ยนหลังค้นหา/cancel/export
8. มี tests ครอบคลุม chunk coverage, boundaries, 10 concurrent requests, partial failure/retry/cancel, dedupe/conflict, exact prompt snapshot และ combined export
